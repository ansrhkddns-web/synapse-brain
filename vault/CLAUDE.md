# SYNAPSE BRAIN 보관함 — 모든 부서 공통 규칙

이 폴더(`vault/`)가 SYNAPSE BRAIN의 기억이다. 작업·결정·보고서·일지는 전부 여기 마크다운 파일로 남는다. 화면은 이 파일들을 읽어 보여 줄 뿐이니, **파일 형식을 지키는 것이 곧 화면에 제대로 뜨는 것**이다.

자기 부서 규칙은 `부서/<부서명>/규칙.md`에 있다. 이 문서와 부딪히면 이 문서를 따른다.

## 폴더

| 폴더 | 파일 이름 | 내용 |
|---|---|---|
| `부서/<부서명>/규칙.md` | 고정 | 부서 역할·작업 폴더·지킬 것 |
| `부서/<부서명>/하위/<이름>.md` | 하위 이름 | 부서 안의 하위 항목(팀·시리즈·채널). 작업의 `unit`으로 묶는다. 부서·하위 문서의 `match`(경로 조각 목록)는 PC에서 도는 바깥 세션·AI 프로그램을 이 자리 일로 볼 때 쓴다. `commands`(이름 → PowerShell 명령, 상태를 바꾸는 것은 `{run, confirm: true}`)는 화면의 하위 항목 패널 버튼이 된다. 만들고 고치기는 `mcp__brain__save_unit`(비서실은 모든 부서, 다른 부서는 자기 부서) |
| `부서/<부서명>/공정/<이름>.md` | 공정 이름 | 하위 항목의 작업 프로세스: 단계 목록(`stages`), 지금 단계(`stage`), 지금 작업물(`item`), `가동`·`정지`. 돌지 않아도 지도에 늘 뜬다. 공정을 돌리는 세션은 단계가 넘어갈 때 `stage`·`item`·`updated`를 고친다. `steps`(단계별 실행 정의: `do` 세션 지시 / `cmd` 명령, `gate` 승인, `group` 렌더·LLM·업로드, `check` 끝났다는 표시 경로)가 있으면 화면의 공정 패널에서 단계를 실행·승인·이어하기 한다(실행기가 `phase`·`run`을 적는다) |
| `작업/` | `W-YYMMDD-NNN.md` | 일 하나 = 파일 하나 = 세션 하나 |
| `결정/` | `D-YYMMDD-NNN.md` | 사람에게 고르게 할 선택지 |
| `보고서/` | `R-YYMMDD-NNN.md` | 조사·결과 보고서 |
| `일지/` | `YYYY-MM-DD.md` | 하루 계획과 요약 (비서실이 씀) |
| `기억/` | `주인말-YYYY-MM-DD.md`, `검수-YYYY-MM-DD.md` | 사람이 화면에서 한 말(지시·이어서·결정·질문)과 검수 판정. **서버가 자동으로 쌓는다 — 세션은 읽기만** |
| `기억/카드/` | `K-YYMMDD-NNN.md` | 기억 카드: 사람이 승인한 규칙 한 줄(적용 부서·하위, 근거 기록). 맞는 카드가 세션 지시문에 붙는다 — **반드시 지킨다** |
| `지표/KPI.md` | 고정 | 화면 상단에 띄울 목표 지표 |
| `템플릿/` | 종류 이름 | 새 파일을 만들 때 복사할 틀 |

- 번호 `NNN`은 같은 날, 같은 종류 안에서 001부터 차례로 붙인다. 쓰기 전에 폴더를 보고 다음 번호를 정한다.
- 날짜는 한국 시간이다. 시각은 `2026-10-30T07:00` 형식으로 쓴다.

## 파일 맨 위 (frontmatter)

모든 파일은 `---`로 감싼 YAML로 시작하고, `type:`으로 종류를 밝힌다. 칸 이름과 허용 값은 `템플릿/`의 틀과 같다. 틀에 없는 칸은 만들지 않는다.

링크는 `"[[W-261030-001]]"`처럼 **따옴표 안의 이중 대괄호**로 쓴다. 본문에서도 다른 파일을 말할 땐 `[[ID]]`로 링크한다 — 화면이 이걸로 역링크와 지도 선을 그린다.

## 작업 상태

```
대기예약 ──▶ 실행중 ──▶ 검수 ──▶ 완료
              │  ▲
              ▼  │
            결정대기                      (어느 단계에서든 ──▶ 취소)
```

| 상태 | 뜻 | 누가 바꾸나 |
|---|---|---|
| `대기예약` | 정해진 때(`schedule`)를 기다림 | 비서실·사람 |
| `실행중` | 부서가 일하는 중 | 부서 |
| `결정대기` | 사람이 골라야 진행 가능 | 부서 (결정 파일을 만들 때) |
| `검수` | 일은 끝났고 사람이 확인할 차례 | 부서 |
| `완료` | 사람이 확인함 | **사람만** |
| `취소` | 하지 않기로 함 | 사람 |

상태를 바꿀 때마다 `updated`도 함께 고친다.

## 일하는 방법

> 두뇌 서버가 띄운 세션이라면 아래 1~4를 `mcp__brain__` 도구(`log_progress`, `request_decision`, `submit_result`, `create_task`, `write_report`)로 한다. 하위 항목·공정은 `save_unit`·`save_process`로 만들고 고친다. 작업·결정 파일을 직접 고치는 것은 서버가 막는다.

1. **진행 로그**: 의미 있는 단계마다 작업 파일의 `## 진행 로그`에 `- HH:MM 한 줄 요약`을 덧붙인다. 긴 출력은 붙이지 않는다.
2. **결정 요청**: 사람이 골라야 하면 멈추고
   - `결정/`에 결정 파일을 만든다(선택지 2~4개, `recommended`에 추천 번호, 본문에 근거),
   - 작업의 `status`를 `결정대기`로, `decision`에 그 결정 링크를 넣는다.
   - 사람이 고르면(`choice`가 채워지면) 작업을 `실행중`으로 돌리고 이어서 한다.
3. **결과**: 결과물 위치(절대 경로)나 보고서 링크를 `## 결과`에 적고 `status: 검수`로 바꾼다. 스스로 `완료`로 바꾸지 않는다.
   - 결과 칸 안의 머리말은 `###` 아래만 쓴다(`##`는 칸 머리말과 겹친다 — 서버는 한 단계씩 내려 적는다). 결과물 경로·보고서 링크는 끝의 `### 결과물` 아래 `- \`절대 경로\`` · `- [[R-…]]` 목록으로(`submit_result`의 `paths`·`reports`가 이렇게 쓴다).
4. **오래 걸리는 일의 진행률**: 렌더·번역 배치처럼 몇 분 넘게 도는 일은 작업 id로 신호를 남겨 화면에 %·남은 시간이 뜨게 한다.
   - ffmpeg: `node "{{BRAIN}}\app\scripts\ffprog.mjs" <작업 id> --step 이름 -- <ffmpeg 인자>` (우선순위·`-threads 10`·중지 버튼 처리까지 해 준다)
   - 파이썬: `app\scripts\brainbeat.py`의 `beat(id, step=…, done=…, total=…, unit=…)`, 항목마다 `stop_requested(id)`를 보고 멈춘다. 끝나면 `beat(id, finished=True)`.
   - 그 밖: `node app\scripts\beat.mjs <id> --step … --done N --total N`
5. **새 결과물 폴더**는 `{{WORK}}\` 바로 아래에 만들지 않는다. `{{BRAIN}}\부서작업\<부서>\<하위 항목>\`에 만들고, 그 하위 항목의 `workdir`를 이 폴더로 둔다(하위 항목이 없으면 함께 만든다). 자세한 규칙은 `부서작업\README.md`. 원래 따로 있던 독립 프로젝트는 제자리에서 일한다.
6. **다른 부서 일**이 생기면 직접 하지 말고, 새 작업 파일을 그 부서 앞으로 만들고 `parent`에 지금 작업을 링크한다.

## 지킬 것 (사용자 전역 규칙 요약)

- 모든 글은 한국어로 쓴다. 코드·파일명·고유명사만 원래 언어로.
- 파일을 영구 삭제하지 않는다. 지울 땐 휴지통으로 보낸다.
- `cd`로 작업 폴더를 옮기지 않는다. 절대 경로를 쓴다.
- 다운로드는 합쳐서 4 MB/s, 업로드는 2 MB/s 이하. 동시 전송·외부 생성 작업은 2개까지.
- 오래 걸리는 작업(ffmpeg, 대량 변환, GPU 작업)은 BelowNormal 우선순위로, ffmpeg는 `-threads 10` 이하.
- 결과물·대용량 파일은 C: 말고 D: 또는 E:에 둔다.
